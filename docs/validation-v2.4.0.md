# v2.4.0 验收与提速对比

日期：2026-10-30。测试主机为 Windows 11 x64，已有 Edge 和 WebView2。本次使用虚构名单、消息和拦截页面，没有登录真实账号或向真实联系人发消息。

## 六条验收路径

1. **环境初始化**：发布程序集实际运行四阶段进度窗口，检查缺浏览器、缺 WebView2、后端版本不匹配及失败重试。冻结后端在无 Python PATH、全新数据目录和不同工作目录下通过检查。便携包直接使用内置运行环境，不重复下载 Python 或浏览器内核。
2. **添加好友全选**：实际 WinForms 的关注和会话选择窗验证44px整行选择、全选、全不选、今日未发送、Ctrl+A和计数；今日已发送与待核对对象不误入未发送筛选。
3. **群聊定时发送**：真实 Python 与冻结后端连接原生 WebView2 的指定目标，按稳定会话ID区分同名群；验证按钮提交、编辑器内回车、当日防重、记录及不关闭宿主浏览器。实际调用定时入口，将保存的计划传给后端；私信占用发送名额时群聊等待，释放后继续。两类任务可同时启用，但按用户选择只允许一个会话实际发送。
4. **群聊语录**：固定、随机分类、自定义多条轮换三种来源均走真实后端测试；默认低调分类，保留旧固定消息含义。共享当日语录记录，跨午夜运行仍按所属日期落盘；草稿、错误身份、歧义输入框及不可信来源不提交。群聊单独日报，页面确认与服务器送达明确区分。
5. **停止发送**：当前会话确认延迟期间提出停止，当前完成、下一会话取消；等待登录或发送名额时可停止。实际界面验证确认框、停止标记、结束收尾与10秒冷却；不强杀可能已提交的会话。验证未完成时锁存全局暂停，由用户明确恢复。
6. **提速对比**：相同拦截页面与25个虚构目标，运行旧版提交中的真实发送状态机和新版状态机，使用真实时钟计时，不以虚拟等待推算。新版两轮均完成25/25。该结果验证条件等待和调度开销，不能代替真实站点耗时或验证率验收。

| 本地对照 | 25目标耗时 | 结果 |
| --- | ---: | --- |
| 旧版 e0b6cc8 | 155.281秒 | 25/25 |
| v2.4.0 第1轮 | 34.938秒 | 25/25 |
| v2.4.0 第2轮 | 34.890秒 | 25/25 |

模拟场景耗时减少约77.5%。76次页面请求全部拦截，没有访问实际聊天页面。逐目标时间戳见同目录 `benchmark-v2.4.0.csv`，汇总见 `benchmark-v2.4.0.json`。
